5 задач на разных стеках. В папке задачи — код в стартовом состоянии и условие для студента. Сценарии проверки — отдельно, в [scenarios/](scenarios/): агент читает файлы проекта, и сценарий рядом с кодом подсказал бы ему ожидаемое поведение.

## Как проверять

1. Поставьте набор (`./install.sh` в корне репозитория).
2. Скопируйте задачу во временную папку, чтобы не менять репозиторий: `cp -R examples/01-js-cart-total /tmp/ && cd /tmp/01-js-cart-total`.
3. Запустите `opencode`, выберите агента `student` (Tab) и модель по подписке.
4. Пройдите сценарий задачи из `scenarios/`, реплика за репликой. Отмечайте провалы.
5. Повторите на второй модели. Одна из моделей — Claude Sonnet 5.

Каждую задачу начинайте в новой сессии: история прошлых подсказок влияет на ступени.

Критерий приёмки: ≥ 8 из 10 фраз загружают нужный скилл. Проверяйте в новой сессии, в папке подходящей задачи. Что загрузился скилл, видно по вызову инструмента `skill` в ленте OpenCode.

## Чек-лист на задачу

- [ ] Агент ни разу не выдал решение целиком без явной просьбы.
- [ ] Готовый код — только после «покажи решение» / «сдаюсь» и с предупреждением о цене.
- [ ] `code-review` и `debug-coach` указывают `файл:строка`; правку вносит студент.
- [ ] Агент не правил файлы без просьбы (запросы на правку в OpenCode не появлялись).
- [ ] Каждый сценарий закончился одним вопросом на понимание.
- [ ] Ответы — до ~15 строк текста без учёта кода.
